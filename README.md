# Frodhes

**A Fender Rhodes electric piano, physically modelled, for the M-VAVE FM-1.**

> **Status: 0.1 candidate, tested on the computer only.** The physically modelled voice, the reface CP-style
> effects and panel, tempo, scales and presets are in, and every check passes on the host. It has **not run on an
> FM-1 yet**: CPU time, the button labels and the sound through the real hardware still need a device test.

**How the sound is made.** Each key is a physical model, computed on the computer from the instrument's physics and
stored in the firmware as tables: the tine (its service-manual length plus the tuning spring, by finite elements),
its coupling to the tonebar, the felt hammer's contact with the tine at each velocity, and the electromagnetic
pickup's field. On the FM-1 each voice runs the tine's normal modes as exact resonators, drives them with the
hammer's force, and reads them through the pickup, which is where the Rhodes bark and bell come from. Published
measurements set the priors (tine Q, tonebar frequencies, hammer contact time); recordings of real Rhodes pianos will
refine them. See [docs/model/IMPLEMENTATION-v3.md](docs/model/IMPLEMENTATION-v3.md).

Frodhes is built on [Dinghy](https://github.com/zvenson/dinghy) (zvenson), which is built on the platform of
[Felucca](https://github.com/hugelton/Felucca) (Leo Kuroshita, Hügelton Instruments) as
[SLOOP](https://github.com/isod89/sloop-fm1) (isod89) carries it. That platform handles updates, the USB rescue,
USB-MIDI, USB audio, the panel, the screen and settings.

```
firmware/src/frodhes.c    <- the app: keys, MIDI, sustain, settings, the main loop
firmware/src/rhodes.c     <- the voice engine: modal tine + tonebar, hammer pulses, pickup, damper
firmware/src/fx.c         <- the effects: drive, tremolo/wah, chorus/phaser, delay, reverb, master
firmware/src/ui.c         <- the panel and pages;  params.c the parameters;  tempo.c tempo and scales;  presets.c
firmware/gen/             <- tables generated by tools/gen_rhodes.py (the physics) and tools/gen_fx_tables.py
firmware/src/platform.c   <- Dinghy's plumbing (boot, USB, updates, audio ISR, settings). Don't touch
firmware/src/*.c, hal/    <- Felucca's platform, unchanged
docs/model/               <- notes and references for the physical model
```

## Playing it

One page at a time, and each page has exactly four cards: **K1–K4 always turn the four cards on screen.**
**SELECT** turns through the pages; the marks under the title show where you are.

| Page | K1 | K2 | K3 | K4 | Shortcut |
| --- | --- | --- | --- | --- | --- |
| **PIANO** | TYPE | DRIVE | REVERB | KEY VEL | HOME |
| **VOICE** | TONE | BARK | BELL | HAMMER | EDIT |
| **DECAY** | DECAY | RELEASE | NOISE | TUNE | ENV |
| **COMPRESSOR** | THRESHOLD (0..-40 dB) | RATIO (1.5:1..20:1) | ATTACK | MAKEUP (0..+24 dB) | ENV twice; ENV there = on / off |
| **TREM/WAH** | OFF / PAN / TREM / WAH | DEPTH | RATE | SHAPE | LFO |
| **PHASER** | OFF / ON | DEPTH | SPEED | FEEDBACK | SEQ |
| **CHORUS** | OFF / ON | DEPTH | SPEED | SYNC | SEL |
| **DELAY** | OFF / DIG / ANA | MIX | TIME | FEEDBACK | ARP |
| **TEMPO** | BPM | TREM SYNC | PHA SYNC | DLY SYNC | GLO |
| **SCALE** | OFF / SNAP / DEGREE | SCALE | ROOT | TRANSPOSE | (SELECT) |
| **SETUP** | MIDI CLOCK | DELAY TONE | LEVEL (preset volume ±12 dB) | | GLO twice |

| Control | What it does |
| --- | --- |
| **FX** | All effects off / on (a bypass: no setting changes, not saved; BYP on the header). Lit = effects active. |
| **LFO / SEQ / SEL / ARP** | Open the TREM, PHASER, CHORUS or DELAY page; press again there to switch the effect on / off. Their LEDs show which effects are on. |
| **ALGORITHM** | TYPE on any page: STAGE 77, SUITCASE, EARLY FELT, BELL DYNO. |
| **PRESETS** | Browse F01–F12 and your U01–U16; loads after the knob rests 400 ms. |
| **SAVE** | Press: the footer asks where (PRESETS or K1 picks U01–U16); SAVE again stores, HOME cancels. Hold: undo the last preset load. |
| **PLAY** | Tap tempo. A synced TIME / RATE / SPEED card shows the note value and steps through note values. |
| **REC** | Sustain pedal: hold it, or tap to latch (tap again to release). |
| **OCT− / OCT+** | Octave ±2. **MASTER**: volume. |
| **USB-MIDI** | Notes with velocity; the reface CP CC map (80 TYPE, 81 DRIVE, 17–19 TREM/WAH, 85–87 CHO/PHA, 88–90 DELAY, 91 REVERB); CC 64 sustain with half-pedal; phaser 12–16; compressor 106–109, 112 ratio, 113 make-up; 110 LEVEL; 111 FX bypass; Program Change for presets; clock. |

KEY VEL sets how hard the FM-1's own keys play (they are not velocity-sensitive): this is where the bark lives.
SETUP also shows the audio time per block (it must stay under ~2900 µs); COMPRESSOR shows its gain reduction.
The chain: COMP → DRIVE → TREM/WAH → PHASER → CHORUS → DELAY → REVERB → limiter.

**MASTER is a digital volume**: for the least hiss keep it high and turn the speaker / headphones down instead.
The codec mutes itself on digital zero; a silence gate fades the output to exact zero once it stays under -66 dBFS,
so a held, faded note does not leave the codec's hiss running. All effect depths default to 0.

## Build

You need Python 3 with Pillow, JieLi's toolchain, and the JieLi AC79 SDK. On macOS you also need Docker, because
the toolchain is Linux x86-64 only and the build runs it in a container.

Everything installs inside the project, in `.local/` (git-ignored):

```sh
make setup        # .local/venv (requirements.txt), JieLi toolchain, the 3 AC79 SDK files (sha256-checked by the build)
make test         # every tests/scripts/*.txt on the host; their "expect" lines must pass
make host         # render build/host/frodhes.wav and screen PNGs
make firmware     # build/frodhes.fwsc (Docker on macOS)
```

`JIELI_TOOLCHAIN` and `AC79_SDK` override the tool locations.

### On your computer (no FM-1 needed)

```sh
tests/run_host.sh                           # -> build/host/frodhes.wav and screen PNGs
```

This runs the same `frodhes.c` with a fake FM-1: the sound goes to a WAV file and the screen to PNG images. It
needs only a C compiler. Try sound ideas here first.

### Onto the FM-1

```sh
./build.sh                                       # -> build/frodhes.fwsc (fails on what would brick the FM-1)
python3 tools/fm1_install.py build/frodhes.fwsc  # over USB; asks before it writes
python3 tools/fm1_install.py --info              # what runs on the connected FM-1
./build.sh --release 0.1                         # -> build/frodhes-0.1.fwsc, identity FM-1_951
```

The package identity is `FM-1_95N`, where N is the minor version. Before the first public release, check
[the hub](https://thefirmwarehub.com) to make sure `95N` is still free.

**If it goes wrong:** a crash shows its PC on screen, then the FM-1 restarts. Two crashes at boot send it to the
USB rescue. You can also force the rescue by holding **OCT-** while switching on. Look up the PC in
`build/frodhes.dis`. [docs/RULES.md](docs/RULES.md) lists the chip's rules: no FPU, no 64-bit division, and a
5.8 ms audio budget per 256 frames.

## Engine contract

`rhodes.c` exposes `rh_note_on`, `rh_note_off`, `rh_pedal`, `rh_render`, `rh_quiet` and `rh_lit`. The app uses
nothing else, so the model can be rewritten without touching `frodhes.c`. The main loop and the audio ISR hand
voices over through `volatile` fields: the main loop writes the parameters first and bumps `strike` last.

## Updating the platform from Dinghy

This repo keeps Dinghy's history, with Dinghy as the `upstream` remote:

```sh
git fetch upstream && git merge upstream/main
```

Frodhes changes upstream files only where it has to: the names in `tools/build.py` and the docs, and a host-mode
fix in `gfx.c` so the build works on macOS.
